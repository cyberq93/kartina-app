# pbn_engine — движок картин по номерам (БыстроФото)

## Статус

Рабочий прототип v1, проверенный автотестами на синтетических изображениях.
**Ещё не прогонялся на реальных фото Дениса и не калиброван на реальную
палитру красок** — это следующий шаг, он требует данных от вас (см. ниже).

## Что внутри

| Модуль | Что делает | Тесты |
|---|---|---|
| `pbn_engine/mixing.py` | Подбор смеси красок под цвет (упрощённая двухконстантная Kubelka-Munk) | `tests/test_mixing.py` — 8/8 |
| `pbn_engine/segmentation.py` | Разбиение фото на регионы (SLIC + слияние по графу соседства) | `tests/test_segmentation.py` — 4/4 |
| `pbn_engine/pipeline.py` | Сборка: фото → разметка с номерами + раскраска | `tests/test_pipeline.py` — 3/3 |
| `pbn_engine/export_pdf.py` | Печатный PDF: лист разметки под размер холста + лист палитры с рецептами | `tests/test_export_pdf.py` — 3/3 |
| `pbn_engine/api.py` | HTTP API для сайта (Flask) — отдаёт 2 картинки, без рецептов | `tests/test_api.py` — 4/4 |
| `pbn_engine/palette.py` | Палитра красок — **сейчас плацехолдер**, см. ниже | — |

## Как запустить тесты

```bash
cd pbn_engine
for f in tests/test_*.py; do python3 "$f"; done
```

## Как запустить API локально

```bash
python3 -m pbn_engine.api
# сервер поднимется на http://localhost:8000
curl -F "photo=@foto.jpg" -F "n_colors=24" http://localhost:8000/process -o result.zip
```

## ЧТО НУЖНО ОТ ВАС, чтобы перейти от прототипа к бою

1. **Реальная палитра красок Дениса.** Сейчас используется
   `PLACEHOLDER_PALETTE` из `palette.py` — условные 12 акриловых цветов "на
   глаз". Пришлите список реальных тюбиков (бренд + фото мазка на белом
   листе при дневном свете, либо просто номер по каталогу производителя) —
   я соберу из них `palette.json` и переключу движок на него через
   `load_palette_from_json()` (или переменную окружения `PBN_PALETTE_PATH`
   для API) — код пайплайна менять не придётся.

2. **2-3 реальных тестовых фото** — желательно портреты со сложной кожей
   (то, на чём "спотыкалась" Раскраска 2.0), чтобы прогнать движок на
   настоящих данных и посмотреть глазами, а не только на синтетике.

3. **Решение по размерам холста для PDF** — сейчас `export_pdf.py` принимает
   `canvas_width_cm`/`canvas_height_cm` как параметры вызова; нужно решить,
   откуда эти значения будут приходить в бою (фиксированный список 15
   размеров из брифа, или свободный ввод).

## Известные ограничения v1 (зафиксированы сознательно, не случайные баги)

- **Модель смешивания — упрощённая, поканальная.** Не воспроизводит
  спектральный "переход" синий+жёлтый→зелёный так же хорошо, как полная
  спектральная модель (Mixbox/Jakob-Hanika). На телесных/земляных тонах
  (ваш приоритет №1) работает корректно — там такой переход не нужен. План
  апгрейда есть в докстринге `mixing.py`.
- **API синхронный.** Если обработка одного фото станет занимать больше
  ~15-20 секунд в реальной нагрузке — нужно будет перевести `/process` на
  асинхронный режим (задача + отдельный запрос за результатом). Это
  изменение локально для `api.py`, остального движка не касается.
- **Разметка в PDF выглядит пиксельной на низком разрешении** — это
  свойство исходного фото, не баг; на реальных фото с камеры будет гладко.
- **Близкие по цвету регионы иногда получают разные, но очень похожие
  номера** (видно в тестовом прогоне: №2,3,7,9,10,11 — все "белила+сиена"
  в разных пропорциях). Для реальных фото с более разнообразными цветами
  это менее заметно, но для продакшена стоит добавить шаг "слияния похожих
  рецептов" — пока не делал, чтобы не усложнять v1 раньше времени.
