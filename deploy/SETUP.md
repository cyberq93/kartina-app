# Настройка серверного ПК

Цель: один изолированный ПК, на котором работает только этот сервис. Наружу
виден единственный путь: исходящий туннель к сайту. Ни одного входящего
порта на роутере.

**Статус: инструкция написана, но на реальном ПК ещё не проверялась.**
Выполняйте шаги по порядку и после каждого проверяйте результат. Если что-то
не совпало с описанием, остановитесь и разберитесь, не пропускайте.

## Что понадобится

- ПК с Xeon 2678v3 (отдельный накопитель под систему, второй накопитель
  под образ-копию).
- Флешка с Ubuntu Server 24.04 LTS (Windows не подходит: принудительные
  обновления и перезагрузки).
- Домен на ваше имя и аккаунт Cloudflare (бесплатного тарифа достаточно
  для туннеля).
- Telegram-бот для оповещений (создаётся у @BotFather за пару минут).
- Внешний сервис проверки доступности (UptimeRobot или аналог).

## Перед началом: персональные данные (152-ФЗ)

Сервис принимает фото клиентов. До запуска на реальных клиентах нужны:
уведомление Роскомнадзора, письменное согласие клиента, политика
обработки на сайте. Проверьте их с юристом. Код сам ничего не пишет на
диск: фото живёт только в памяти на время обработки.

## 1. BIOS

- Включить «Restore on AC Power Loss» / «Power On after power failure»:
  после отключения света ПК сам включится.
- Отключить загрузку с USB/сети после установки, поставить пароль на BIOS.

## 2. Установка Ubuntu Server

- Минимальная установка, без дополнительных пакетов.
- Диск шифровать (LUKS) только если готовы вводить пароль после каждой
  перезагрузки. Для ПК, который сам поднимается после отключения света,
  это неудобно. Тогда безопасность держится на физическом доступе к
  машине; решите это сознательно.
- Создать обычного пользователя-администратора. Вход по SSH только по
  ключу (шаг 4).

## 3. Политика обновлений

Полностью без обновлений нельзя: пока ПК выходит в интернет через туннель,
в старых версиях ОС и Python со временем находят уязвимости. Рабочая схема:

- Автообновления выключены. Ничего не меняется само.
- Раз в 3–6 месяцев вы вручную: собираете обновлённую систему на запасном
  накопителе, прогоняете тесты (`python3 tests/test_*.py`), проверяете на
  тестовых фото и только потом переключаетесь на неё.
- Сразу, вне графика, обновляйтесь при громких уязвимостях в используемых
  компонентах (Python, OpenSSL, ядро, cloudflared). Подпишитесь на
  рассылки безопасности Ubuntu.
- Хотя бы раз после установки выполните `sudo apt update && sudo apt
  full-upgrade`, чтобы зафиксировать уже исправленное состояние.

## 4. Закрыть всё лишнее

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw enable
```

Входящий SSH разрешайте только из вашей локальной сети:
`sudo ufw allow from 192.168.0.0/16 to any port 22 proto tcp` (подставьте
свою подсеть). В `/etc/ssh/sshd_config`: `PasswordAuthentication no`,
`PermitRootLogin no`, затем `sudo systemctl restart ssh`. Сначала
скопируйте на ПК свой SSH-ключ и убедитесь, что вход по нему работает.

Проверка с другого компьютера вне вашей сети: `nmap -Pn ВАШ_ВНЕШНИЙ_IP`
не должен показывать ни одного открытого порта.

## 5. Пользователь и код сервиса

```bash
sudo useradd --system --home /opt/pbn --shell /usr/sbin/nologin pbn
sudo mkdir -p /opt/pbn /etc/pbn
sudo apt install -y python3-venv python3-pip git
sudo git clone https://github.com/cyberq93/kartina-app /opt/pbn/app
sudo python3 -m venv /opt/pbn/venv
sudo /opt/pbn/venv/bin/pip install -r /opt/pbn/app/requirements.txt
sudo chown -R root:root /opt/pbn      # код сервису доступен только на чтение
```

Для частного репозитория понадобится токен доступа GitHub или ключ
развёртывания (deploy key) только на чтение.

Затем зафиксируйте версии: `sudo /opt/pbn/venv/bin/pip freeze` и внесите
точную версию `gunicorn` в `requirements.txt`.

Прогоните тесты на самом ПК:

```bash
cd /opt/pbn/app && for f in tests/test_*.py; do sudo -u pbn /opt/pbn/venv/bin/python3 "$f"; done
```

(тестам нужна запись в `output/`; если права мешают, запускайте под своим
пользователем.)

## 6. Секреты и запуск сервиса

```bash
openssl rand -hex 32            # это будущий PBN_API_KEY
sudo cp /opt/pbn/app/deploy/pbn.env.example /etc/pbn/pbn.env
sudo nano /etc/pbn/pbn.env      # вписать ключ и (позже) токен Telegram
sudo chown root:root /etc/pbn/pbn.env && sudo chmod 600 /etc/pbn/pbn.env
sudo cp /opt/pbn/app/deploy/pbn.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now pbn
curl http://127.0.0.1:8000/health    # должно вернуть {"status":"ok"}
```

Файл `pbn.env` не должен попадать в репозиторий и в резервные копии,
которые лежат где-то в открытом виде.

## 7. Проверка защиты на самом ПК

```bash
curl -i -F "photo=@любое.jpg" http://127.0.0.1:8000/process
# ожидаем 401 (нет ключа)
curl -i -H "X-API-Key: ВАШ_КЛЮЧ" -F "photo=@любое.jpg" http://127.0.0.1:8000/process -o /tmp/r.zip
# ожидаем 200 и zip с двумя картинками
```

## 8. Туннель (без открытых портов)

1. Установить `cloudflared` по официальной инструкции Cloudflare для Ubuntu.
2. `cloudflared tunnel login`, затем `cloudflared tunnel create pbn`.
3. Привязать имя: `cloudflared tunnel route dns pbn api.ВАШ-ДОМЕН.ru`.
4. Скопировать `deploy/cloudflared-config.example.yml` в
   `/etc/cloudflared/config.yml`, вписать идентификатор туннеля и домен.
5. `sudo cloudflared service install` и `sudo systemctl enable --now cloudflared`.
6. Проверить снаружи: `curl https://api.ВАШ-ДОМЕН.ru/health`.

Рекомендуется также включить в панели Cloudflare правила для этого имени:
ограничение по частоте запросов и разрешение только запросов с вашего
сайта. Ключ в сервисе остаётся основной защитой, правила Cloudflare
дополнительный слой.

## 9. Мониторинг

Внутренняя проверка (ловит падение сервиса). Создать две системные
записи:

`/etc/systemd/system/pbn-health.service`:
```
[Service]
Type=oneshot
ExecStart=/opt/pbn/app/deploy/healthcheck.sh
```

`/etc/systemd/system/pbn-health.timer`:
```
[Timer]
OnBootSec=2min
OnUnitActiveSec=5min
[Install]
WantedBy=timers.target
```

Включить: `sudo systemctl enable --now pbn-health.timer`. В `pbn.env`
добавить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

Внешняя проверка (ловит выключенный ПК и пропавший интернет): заведите
в UptimeRobot проверку адреса `https://api.ВАШ-ДОМЕН.ru/health` каждые
5 минут с уведомлением в Telegram или на почту. Эта проверка важнее
внутренней: только она заметит, что ПК вообще недоступен.

## 10. Резервная копия

После того как всё работает, снимите образ системного диска на второй
накопитель (например, Clonezilla, загрузившись с флешки). Повторяйте после
каждого планового обновления. Храните отдельно: файл `pbn.env` (в
менеджере паролей) и данные туннеля Cloudflare.

## Подключение сайта

- Ключ `PBN_API_KEY` хранится только в серверной части сайта (бэкенде).
  **Ни в коем случае не в JavaScript страницы:** иначе любой посетитель
  увидит его в браузере.
- Браузер клиента отправляет фото на ваш бэкенд, бэкенд пересылает на
  `https://api.ВАШ-ДОМЕН.ru/process` с заголовком `X-API-Key`, получает
  zip с `outline.png` и `colorized.png` и отдаёт их на страницу.
- Если сервис не отвечает (таймаут, 429, 503), показывайте клиенту
  понятное сообщение «попробуйте через несколько минут» и не теряйте
  загруженное фото при повторной попытке.
- Таймаут запроса на бэкенде сайта ставьте не меньше 60 секунд.
